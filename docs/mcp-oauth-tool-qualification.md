# Delegated tool effect and retry qualification

Source baseline: API `57c7f1ea5dc9b2d3d6ef26b202735b70c6db1909`, October 26, 2026. This is a source-bound qualification map for [Mono #212](https://github.com/recoupable/mono/issues/212), not a grant of new authority or a claim that every operation is safe to retry. It enumerates every public operation derived from the existing full-scope policy and delegated Context action map, including aliases. It does not add a fixed-count discovery test.

## Common execution boundary

Every row inherits [registerFullOAuthTools](../lib/mcp/oauth/registerFullOAuthTools.ts): reverify the token at call time; require current `mcp:tools`, matching account, client and grant; strict-parse exposed arguments; reject caller `account_id`; bind any internal owner field and Context action on the server. [prepareFullOAuthTool](../lib/mcp/oauth/prepareFullOAuthTool.ts) consumes the shared rate budget, then checks applicable task, artist, organization, catalog, room and recipient references before the business callback. [executeFullOAuthTool](../lib/mcp/oauth/executeFullOAuthTool.ts) adds task-run and Sora locator boundaries. These are sequential checks, not a transaction or a guarantee against authorization changes during an in-flight call.

`RO` and `W` below reproduce the policy's readOnly annotation, not a cost verdict. Rate budgets are request limits, not spend approvals. **Unknown** explicitly means this qualification has not established a domain-wide or provider-wide guarantee. A callback that merely forwards to a provider is not evidence of idempotency. No universal action-confirmation token or retry store exists in this wrapper. Recipient cells describe outbound destinations or their absence at the inspected boundary, not marketing consent.

## Evidence and unresolved decisions

- Existing [SDK catalog coverage](../lib/mcp/oauth/__tests__/fullOAuthCatalog.test.ts) establishes registration/schema exposure; it is not a cost or retry execution test. No replacement discovery/count test was added.
- Existing [registry authority tests](../lib/mcp/oauth/__tests__/registerFullOAuthTools.test.ts), [membership-loss tests](../lib/mcp/oauth/__tests__/membershipLoss.test.ts), [recipient denial tests](../lib/mcp/oauth/__tests__/emailDenial.test.ts), [preparation tests](../lib/mcp/oauth/__tests__/prepareFullOAuthTool.test.ts), and [executor tests](../lib/mcp/oauth/__tests__/executeFullOAuthTool.test.ts) remain distinct evidence. Membership evidence does not establish every organization role rule.
- New [task deletion execution tests](../lib/mcp/oauth/__tests__/taskDeletionDenial.test.ts) use the actual full-scope wrapper, preparation, registered delete callback and `deleteTask` domain. Only data/access/scheduler boundaries are stubbed. They qualify revoked grants, owner override, ownership loss after registration, lookup failure, domain denial and successful call order. Both scheduler and database deletion remain uncalled for denials. An isolated guard-bypass mutation fails the regression; restored source passes. This is callback-level execution, not a new SDK discovery test or a hosted client session.
- The shared [deleteTask](../lib/tasks/deleteTask.ts) deliberately allows broader first-party account access; delegated preparation is stricter. The direct-domain control preserves that behavior. Parallel scheduler/database deletions are not atomic, and this work does not invent a compensation or retry policy. The test does not claim to resolve in-flight owner changes between successive database reads.
- `select_catalog_songs` is read-only in policy but invokes [AI refinement](../lib/catalog/analyzeFullCatalog.ts). `artist_deep_research` and `spotify_deep_research` retain compatibility names but describe saved social-profile retrieval using a Recoup artist account ID. Their callbacks read page 1 with limits 100 and 20 respectively through [getArtistSocials](../lib/artist/getArtistSocials.ts), which queries saved rows and flattens profile fields.
