# Main-agent tool UI count metadata

Bounded successor to existing API649 head `f66620a7726ebe9b521ddd97b2f591ac68e1b39a`, under Mono358. Compared with main `5c0e585d0e12277abc57160129f35b02c9e7cacf`.

The existing atomic audit writer (`recordCreditDeduction`) already accepts `toolCallCount` and maps it into `usage_events.tool_call_count`, defaulting to zero. The workflow and its `handleChatCredits` wrapper do not supply it, so tool-bearing messages arrive as zero. This patch adds the pure SDK-based part counter, passes the accumulated assistant message's count at the existing call site, and forwards that optional metadata through the wrapper. No migration or RPC signature change is included.

Definition: count top-level static/dynamic tool UI parts in the accumulated assistant message using the installed AI SDK's `isToolUIPart`. All tool states count, including pending and errored requests; nested subagent output does not. A resumed assistant message includes its preexisting tool parts in this snapshot count. It is not a count of successful tool executions, incremental newly executed work, unique calls across separate audit records, or nested subagent usage. This does not change or solve existing resume/accounting policy; original651 subagent charging and its usage-diff proposal are separate and not implemented.

The authenticated account, model choice, token/gateway cost inputs, rate conversion, amount, audit writer, auto-top-up path, resource link, retry/step boundaries and number of calls remain unchanged. Optional omission still uses the existing writer's zero default; explicit zero is forwarded. The helper is deterministic and performs no I/O, consistent with the installed Workflow SDK's workflows-and-steps documentation. It does not introduce a step, hook, new run or package upgrade. The held SDKv7 migration remains untouched.

When released and an existing workflow completes, its existing audit-write arguments include the message's count instead of always relying on zero. Actual database persistence, deployed RPC state, production event totals, durable replay, successful execution counts and historical correction are not verified here. Existing rows are not backfilled, and no workflow, provider, credit deduction, auto-top-up or customer job was run during development.

Regression tests run the actual workflow orchestration with mocked steps/credit writer and the actual wrapper with mocked pricing/audit leaves. Six tests failed before the wiring. Tests cover static/dynamic/pending/failed parts, accumulated multi-iteration messages, resumed snapshots, user-stop behavior, explicit zero, unchanged cost inputs/amount and one existing writer call. Unit tests are not compiled durable replay evidence. Clean preview build and CI establish their separately recorded bounded checks. No credentials, database permissions, commercial terms, billing configuration, live records or deployment settings were inspected or changed.
