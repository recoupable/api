# Capture notes from existing track metadata

Bounded successor to existing API687 head `638c133dfd4e06057701a69c6286b2b4c1ade835`, under Mono358. Current API main comparison: `49af795cb0f4336d9ca981a768c7389cae8df218`.

`mapUnmappedAlbumTracks` creates songs and identifier mappings from the existing Spotify batch lookup but does not populate notes. Current Chat `lib/catalog/isCompleteSong.ts` still requires nonempty notes, along with title, creator linkage, album and ISRC. Removing the unused Redis producer in API964 did not add synchronous note formatting. Restoring that queue is not part of this fix.

The old687 proposal invokes `generateTrackNotes` for every resolved track. Inspection shows that helper requests a token and artist genres, despite being described as a cheap template. This successor shares its text formatter instead: `formatTrackNotes` is pure and accepts the fetched track and artist-name text. Capture uses the existing track response and names. No genre, Spotify, Apify, model or paid-provider request is added. The existing manual import path still calls its genre helper before using the shared formatter, with its prior error fallback.

Complete metadata keeps the existing manual text format. Partial metadata produces a shorter factual summary instead of undefined or NaN attributes. Empty titles produce no notes. Capture carries the raw track only through in-memory mapping; it persists the normal song fields plus notes, not the raw provider object. ISRC deduplication, final-record selection, identifier mappings and artist-link calls remain in the existing order.

Production effect when approved and normally deployed: future captures that resolve previously unmapped recordings also include notes in the existing song upsert. No backfill is run. Already mapped recordings bypass this function's enrichment, so simply repeating a capture does not repair old missing notes. This addresses only the notes portion of completeness; rows missing title, creator linkage, album or ISRC may still be hidden. Existing song upsert semantics are retained, including updating a matching ISRC when an unmapped reissue resolves to it.

Tests exercise the actual formatter, capture mapping and manual helper with mocked provider/database leaves. They verify note persistence, artist-link payloads, one song with both reissue identifiers, unchanged batch/token call counts and zero capture genre lookups. Manual genre descriptions and enrichment-failure fallback are checked separately. Existing upstream rate-limit and failure behavior tests remain in place. No real capture, provider/customer/database write, credit/billing operation, migration, access change or deployment setting was performed. Source and CI evidence do not prove customer catalog rendering or live capture outcomes.
