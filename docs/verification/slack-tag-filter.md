# Coding Slack mention author filter

Bounded successor to existing API #338 head `a78de1505e25538e7b778f53873d13f56dc017ba`, under Mono358, compared with main `06ceed29ece8bb2155e1861fc01ed538396dadc6`. Original #338 asks for an optional author filter and a distinct-author options endpoint; both are absent on this base. This ports the recorded behavior onto current admin authentication and collection, not the old branch.

`GET /api/admins/coding/slack` retains its existing `period` values/default and response fields. Optional `tag` is the exact case-sensitive Slack user ID, trimmed before comparison; empty or whitespace-only values return 400 after existing admin authentication. Omission preserves existing behavior. Filtering occurs after the existing period collection and before `total`, `total_pull_requests` and `tags_with_pull_requests` are computed. Unknown IDs yield an empty result with zero totals. This is display filtering, not authorization or a reduction in Slack collection work.

New `GET /api/admins/coding-agent/slack-tags` reuses `validateAdminAuth` directly; no duplicate auth wrapper is needed. It invokes the existing `fetchSlackMentions("all")` once per authorized request, then returns `{ status: "success", total, tags: [{ id, name, avatar }] }`, deduplicated by ID and sorted by display name using `localeCompare`. The first collected profile is retained. Equal names do not merge different IDs. No query parameters are defined for this options route. It returns existing 401/403 auth failures and the existing 500 error shape on thrown collection errors. OPTIONS returns 204 with existing CORS headers without authentication or collection.

The options are authors in data returned by the current collector, not a complete all-time Slack directory. Existing channel access, Slack retention, paginated history, first-page thread reply handling, and partial failures remain unchanged. The filter does not change collectors, tokens, scopes, concurrency, caching, billing, provider models, content triggers or Slack sends. The newly requested options route performs another existing all-period scan when called; no automatic caller, polling, UI, worker or scheduled action is added. A future UI should account for that scan's latency and quota cost rather than assuming free cached options. There is no database/schema migration.

Source tests invoke the actual GET handlers and query validation with admin auth and Slack collection mocked at their external boundaries. They cover filtered/unfiltered totals, omitted/unknown/blank tags, name/ID deduplication, retained profile, empty options, 401/403 exits before collection, thrown collection failure and CORS preflight. Existing shared collector tests retain the bot-parent reply fix from API #1090. Local tests, independent review, CI and preview each establish their recorded source/build checks; no real admin collector, Slack request/send, customer job, provider/credit operation or credential inspection is performed. Production access, history coverage, latency and quotas are not verified here.
