# OAuth MCP annotation behavior inventory

Source baseline: API `b371f5ed2f2cda150de6156d5a3d6b0c5f7afb21`, November 9, 2026. This inventory documents the proposed explicit annotations, not the deployed endpoint or a release approval. Handler behavior, schemas, authentication and scopes are unchanged.

The full OAuth registry contains 89 business tools and two workflow UI entrypoints (91 registered, 90 model-visible). The limited registry contains five business tools and the same two UI entrypoints (7 registered, 6 model-visible). The sidebar entrypoint is app-only. Two legacy deep-research aliases remain in internal policy but are excluded from the full registry. The separate API-key/Privy standard registry has additional tools and is not fully remediated here.

## Classification rules

The [OpenAI plugin guidelines](https://developers.openai.com/plugins/plugin-guidelines#correct-annotation) require explicit `readOnlyHint`, `destructiveHint` and `openWorldHint` booleans. These classifications follow business behavior, not names or HTTP verbs:

- `readOnlyHint=true`: retrieval or computation without saving, sending, starting jobs or otherwise changing business state.
- `destructiveHint=true`: an operation can replace/delete/cancel existing state, irreversibly send or publicly disclose information, or change charged/held account credits. Purely additive private writes remain false.
- `openWorldHint=true`: public/open-ended entities, arbitrary fetched URLs, public disclosure or arbitrary destinations. Network use alone does not make a fixed-provider, private-workspace operation open-world.
- Authentication, rate-limit counters and operational telemetry are distinguished from the business action. These hints do not establish idempotency, cost ceilings or an approval record.

A tool with multiple paths uses the more consequential classification supported by any path.

## Database-backed effects

Database source snapshot: `ebdb549d0b719a95ee7105bb9146c077841411e6`. All migration definitions of the relevant functions were searched; these are repository observations, not verification of deployed migrations.

- [Release pack command](https://github.com/recoupable/database/blob/ebdb549d0b719a95ee7105bb9146c077841411e6/supabase/migrations/20261020150000_release_pack_jobs.sql#L49-L166) settles expired running jobs even on `read`, changes asset/job state and refunds held credits. Therefore `get_release_pack` is a write with destructive effects. Export also updates `exported_at`; prepare and estimate can replace pack state. Generate/retry use private snapshots, while estimate and asset upload can fetch arbitrary URLs.
- [Release review receipts](https://github.com/recoupable/database/blob/ebdb549d0b719a95ee7105bb9146c077841411e6/supabase/migrations/20261008160000_context_release_cases.sql#L131-L152) are immutable/idempotent inserts, not replacements.
- [Brief snapshots](https://github.com/recoupable/database/blob/ebdb549d0b719a95ee7105bb9146c077841411e6/supabase/migrations/20261010010000_context_company_assessment.sql#L31-L66) remain immutable/idempotent inserts in the later company-assessment definition.

## Validation and limits

- Regression tests first reproduced blanket open-world annotations, missing limited-mode booleans, and the incorrect pack-read classification.
- Full repository suite on the final runtime changes: 1,460 files and 9,322 tests passed; 15 files and 45 tests skipped.
- OAuth suite: 52 files and 313 tests passed; two files and five tests skipped. A fresh checkout first needed the normal extension build; the suite passed after that step.
- The final test-only strengthening includes both workflow UI entrypoints in actual SDK discovery: two focused files and six tests passed. Every full-mode tool has all three explicit booleans; semantic assertions independently cover key classifications. Limited-mode tests cover all five business tools.
- `pnpm lint:check`, `pnpm typecheck:mcp-oauth`, changed-file formatting and `git diff --check` passed.
- No live sends, paid generation, publication, deletion or database writes were used as test probes. Environment-gated integration/database tests remain skipped. A production build, deployed migration state and authenticated production `tools/list` were not verified.

Before any release or resubmission, compare authenticated `tools/list` from the exact review endpoint in both OAuth modes with this inventory, including the app-only sidebar. Confirm deployed database behavior, especially pack settlement. If the review endpoint exposes the API-key/Privy standard registry, audit that separate catalog too.

Existing cost, approval and replay limitations in [the delegated-tool qualification map](mcp-oauth-tool-qualification.md) remain open. These annotations neither enforce authorization nor claim that every operation is safe to retry.

## Draft branch deployment guard

`vercel.json` disables automatic deployments only for `fix/mcp-oauth-behavior-annotations`, using Vercel's documented [branch-specific deployment control](https://vercel.com/docs/project-configuration/git-configuration#git.deploymentEnabled). All other branches retain their existing behavior. This lets review and GitHub CI proceed without creating a preview deployment. Removing the guard or deploying the branch requires a separate release decision.
