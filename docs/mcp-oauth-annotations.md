# OAuth MCP annotation behavior inventory

The November 26 audit checked API main at `e4751a0b7967ff697856c23de4ee06a375dd0384` and exercised the OAuth registry through the MCP SDK. The full registry registers 93 tools and two workflow UI entrypoints, of which 94 are model-visible. The limited registry registers six tools and two workflow UI entrypoints, of which seven are model-visible. The sidebar entrypoint is app-only. The selected-context registry uses a narrower projection of the same policies. The API-key and Privy registry has additional tools outside this OAuth audit.

Two internal deep-research aliases are excluded from full OAuth. The daily email aliases use their public names below. Unchanged rows retain their pinned implementation references. This source audit and test run leave the publisher draft unsubmitted.

## Classification rules

[OpenAI's MCP review requirements](https://developers.openai.com/plugins/deploy/app-review) ask for explicit `readOnlyHint`, `destructiveHint` and `openWorldHint` booleans and a reason for each. These rules follow business behavior, including downstream work that an input can enable.

- `readOnlyHint=true` covers reads or computation that return a result without saving, sending or starting a job.
- `destructiveHint=true` covers replacement, deletion, cancellation, irreversible sends or public disclosures, and changes to charged or held account credits. Purely additive private writes use false.
- `openWorldHint=true` covers open-ended public entities, arbitrary fetched URLs, public disclosure and communications outside the workspace. Fixed infrastructure and account-bound private data use false.
- Authentication, rate limits and telemetry are operational. The hints describe business effects. A tool with several paths takes the more consequential classification.

## Database-backed effects

Database source snapshot: `ebdb549d0b719a95ee7105bb9146c077841411e6`. All migration definitions of the relevant functions were searched; these are repository observations, not verification of deployed migrations.

- [Release pack command](https://github.com/recoupable/database/blob/ebdb549d0b719a95ee7105bb9146c077841411e6/supabase/migrations/20261020150000_release_pack_jobs.sql#L49-L166) settles expired running jobs even on `read`, changes asset/job state and refunds held credits. Therefore `get_release_pack` is a write with destructive effects. Export also updates `exported_at`; prepare and estimate can replace pack state. Generate/retry use private snapshots, while estimate and asset upload can fetch arbitrary URLs.
- [Release review receipts](https://github.com/recoupable/database/blob/ebdb549d0b719a95ee7105bb9146c077841411e6/supabase/migrations/20261008160000_context_release_cases.sql#L131-L152) are immutable/idempotent inserts, not replacements.
- [Brief snapshots](https://github.com/recoupable/database/blob/ebdb549d0b719a95ee7105bb9146c077841411e6/supabase/migrations/20261010010000_context_company_assessment.sql#L31-L66) remain immutable/idempotent inserts in the later company-assessment definition.

## Commerce audit

[OpenAI's commerce rules](https://developers.openai.com/plugins/plugin-guidelines#commerce) allow existing subscribers to use included features. They prohibit selling or facilitating the purchase of digital services, plans and credits in the plugin, including upgrade and checkout flows. The October 27 review notice cited commerce without naming a tool or showing the purchase path. The November 9 notice requested annotation corrections.

| Path | Evidence |
| --- | --- |
| Historical automatic credit purchases | This is the strongest historical candidate. A successful API debit could reach the same automatic Stripe top-up as a web debit when the balance crossed the configured threshold. [PR #1194](https://github.com/recoupable/api/pull/1194) restricted that path to web debits. [Current debit guard](../lib/credits/recordCreditDeduction.ts) |
| Historical upsell and card collection paths | PR #1194 removed `billingUrl` from pack MCP errors, neutralized plan-upgrade messages on task create/update and fan-connection denial, and removed retry recovery that started Stripe card setup for Songstats. The last two are adjacent workflow paths. The review notice does not establish whether they were exercised. [PR #1194](https://github.com/recoupable/api/pull/1194) |
| Existing balance and plan usage | Social scrape, music analysis, pack generation/retry, site concept/generation, and scheduled agent runs can use existing credits or plan allowances. Pack estimation saves a quote with a dollar equivalent and credit charge, without debiting or starting checkout. A generation call uses the approved quote. A stale pack read/export can return held credits. The Sora handler starts a provider job without a Recoup account debit. [Pack operations](../lib/content/packs/processPackOperation.ts), [analysis](../lib/flamingo/processAnalyzeMusicRequest.ts), [social scrape debit](../lib/socials/deductSocialScrapeCredits.ts), [site generation](../lib/sites/generateSiteObject.ts), [agent workflow](../app/lib/workflows/runAgentWorkflow.ts), [Sora](../lib/video/generateVideo.ts) |

[Report selection](../lib/tasks/missedReports/findMissedReport.ts), [notice](../lib/tasks/missedReports/sendMissedReportNotice.ts), [plan limit response](../lib/plans/buildPlanLimitBody.ts) |
| Checkout and packaged instructions | Stripe credit and subscription sessions are separate REST routes. Neither is registered by OAuth. ## Validation and limits

- The SDK discovery regression first reproduced the missing open-world annotation on `contact_team`. Its assertions now cover the task and daily-email changes, both launchers and the skills catalog. All 95 full OAuth registrations expose three explicit booleans.
- The audit observed handler and registration behavior in source and local tests. The publisher has not rescanned these changes. No live tool calls that generate media, spend credits, send email or publish content were used as probes.
- Deployment and database state require separate runtime verification. The existing [delegated-tool qualification map](mcp-oauth-tool-qualification.md) covers cost, authorization and replay constraints.

## Draft branch deployment guard

`vercel.json` disables automatic deployments for the original `fix/mcp-oauth-behavior-annotations` branch and the isolated successor `codex/oauth-annotations-current-main`, using Vercel's documented [branch-specific deployment control](https://vercel.com/docs/project-configuration/git-configuration#git.deploymentEnabled). All other branches retain their existing behavior. This lets review and GitHub CI proceed without creating a preview deployment. Removing the guard or deploying either branch requires a separate release decision.
