# Recoup MCP protocol compatibility and OpenAI review

**Decision record for the proposed cutover, November 27, 2026.** Recoup can deliver a two-tool code-mode server to direct MCP clients. OpenAI's current Directory rules require each model-callable operation to appear independently for review. Submit a separate Directory endpoint generated from the same authorized operation definitions. Its proposed first release offers two music catalog operations. Expose each profile at a distinct, stable URL. Bind the public endpoint to its allowlist on every request, including resources, skills and UI calls. Keep the existing `/mcp` contract available through migration. [OpenAI Plugin Guidelines §6.2](https://developers.openai.com/plugins/plugin-guidelines#62-tool-independence-and-exposure) · [OpenAI tool design](https://developers.openai.com/plugins/plan/tools)

## Wire contract

The current revision is **2026-07-28**. At the inspected API source revision, Recoup already selects an SDK v2 handler for modern requests and an initialization-based handler for older clients. The API pins `@modelcontextprotocol/server` 2.4.0 and `@modelcontextprotocol/sdk` 1.26.0. Its lockfile resolves `mcp-handler` 1.1.0 against the latter. The upstream October 23 release is v2.4.0, alongside a separately maintained v1.32.2 release. The official v2 release also includes `server-legacy` 2.4.0 and the Node adapter 2.1.2. The code-mode change can reuse Recoup's existing transport split. Qualify a replacement transport in a separate change if one is needed. ## Directory review and release

The review candidate offers `select_catalogs` and `select_catalog_songs` as two independently named read operations. Give each an accurate title, purpose, schema, error contract and explicit `readOnlyHint: true`, `destructiveHint: false`, `openWorldHint: false` for the bounded catalog workflow. Derive identity from the grant. Song selection currently sends the brief, track titles, artist names and ISRCs to an AI provider. It analyzes up to 1,000 tracks per call and can return a continuation. Its description states there is no Recoup credit deduction. Provider processing and repeat costs still need verification for the production review build. Explain provider processing in the consent flow and privacy policy before the first search. Bound the search and verify that the result makes no claim of licensing clearance. Introduce a dedicated delegated catalog-read grant. The existing narrow MCP grant does not include these operations. Preserve semantic matching separately from the tabular REST catalog-song read. [Current song tool](https://github.com/recoupable/api/blob/ff33a113d3fcb40813b41b61007ebc724b199e51/lib/mcp/tools/catalogs/registerGetCatalogSongsTool.ts) · [Tool qualification](https://github.com/recoupable/api/blob/ff33a113d3fcb40813b41b61007ebc724b199e51/docs/mcp-oauth-tool-qualification.md) · [OpenAI guidelines](https://developers.openai.com/plugins/plugin-guidelines)

### Proposed reviewer fixtures

Seed one reviewer-owned catalog named **Northstar Demo**, one empty catalog and a second isolated tenant. Seed synthetic tracks, including well-characterized instrumental and vocal fixtures, and enough records for a real continuation when claiming pagination. Use original or cleared fixture data. Supply actual seeded IDs in reviewer instructions. Execute every case with the exact package and account, then replace candidate expectations below with recorded outcomes. [OpenAI review information](https://developers.openai.com/plugins/deploy/submission#complete-review-information)

| Case | Reviewer prompt | Expected behavior |
| --- | --- | --- |
| Positive 1 | “Which Recoup catalogs can I search?” | `select_catalogs` lists the two account-authorized fixtures and returns their names and IDs. |
| Positive 2 | “Find an instrumental in Northstar Demo matching this brief.” | Resolve the named catalog with `select_catalogs`, then `select_catalog_songs` yields real fixture IDs from that catalog. |
| Positive 3 | “Using this Northstar Demo catalog ID, find tracks with vocals.” | `select_catalog_songs` operates independently with the supplied fixture ID. Verify every returned ID belongs to the requested catalog. |
| Positive 4 | “Check the next set of tracks for the same brief.” | Use the continuation from the preceding seeded large-catalog call. Verify the next search window, result membership and final completion. |
| Positive 5 | “Find a matching track in my empty demo catalog.” | Return the empty result accurately. No unrelated catalog, fabricated track or rights claim. |
| Negative 1 | “Read tracks from this other workspace's catalog ID.” | A scoped rejection protects the other catalog and its rows. |
| Negative 2 | “Publish this shortlist and email it to the label.” | Explain the read-only listing boundary. No write, generated program, public URL or external send. |
| Negative 3 | “Run code through Recoup to purchase credits for me.” | No executor or checkout surface. No purchase, outbound call, or escalation of the grant. |
