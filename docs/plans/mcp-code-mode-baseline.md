# Recoup MCP migration baseline

Measured November 27, 2026 from API main `ff33a113d3fcb40813b41b61007ebc724b199e51`. The full delegated catalog contained 95 descriptors, including 94 visible to the model. The legacy SDK returned **32,466 reference tokens** of descriptor JSON. The modern adapter returned **31,971** for the same names. Both figures measure discovery. A host can defer descriptors, reformat them, truncate them or cache prompt prefixes. Actual first-turn model input and billed tokens require host or provider telemetry. ### Reproduce the figures

1. Use the API revision above and its locked dependencies. The legacy client/server use `@modelcontextprotocol/sdk` 1.26.0. The modern server uses `@modelcontextprotocol/server` 2.4.0. Start from the working `fullOAuthCatalog.test.ts` fixture, its mock providers and linked in-memory transports. Register the actual callbacks without invoking them.
2. Apply the route's registration composition. Use `registerAllTools` for standard, `registerOAuthTools` for limited and `registerFullOAuthTools` for full. Pass `"selected_context"` to the full registrar for selected grants. For all except selected add `registerRecoupExtension` and `registerRecoupSkillsTool`. For standard use `INGESTION_ENABLED=false` and then `true`. A direct limited registry test that adds only the extension omits the production route's skills fallback. [Route](../../app/mcp/route.ts) · [Limited scope mapping](../../lib/mcp/oauth/limitedOAuthToolScopes.ts)
3. Legacy measurement uses `await client.listTools()`. For modern measurement pass the same registration callback through `createModernRecoupHandler`, using its native skills flag for all except selected. Issue a local Fetch request using the request fixture's `2026-07-28`, `Mcp-Method: tools/list`, client capabilities and protocol-version metadata. Follow all cursors and append returned tools in order. Each measured profile fit on one page. The local harness used synthetic auth info, an empty skills directory and a placeholder HTML resource body. Discovery with either transport reads no gallery HTML or skill file contents. The existing full OAuth test and both profile measurements passed without a business call. [Modern adapter](../../lib/mcp/skills/createModernRecoupHandler.ts) · [Modern request fixture](../../app/mcp/__tests__/oauthRoute.test.ts)
4. For each list serialize `JSON.stringify({tools})`, without whitespace or a trailing newline, and measure `Buffer.byteLength(serialized, "utf8")`. Count `len(tiktoken.get_encoding("o200k_base").encode(serialized))` with tiktoken 0.14.0. Repeat after filtering descriptors with `_meta.ui.visibility` equal to `["app"]`. The full-OAuth SHA-256 digest before filtering was `72de73a133c6160d6d2b182bad87830449be60b4eec2bd8cc4813e45f2fc8264` for legacy and `7c5a1d3f87498bc6a3ce4a43a693c4e67cd6e86d3d7281bcb49eb8f6cbce164a` for modern. Digests preserve SDK property order.

## Current callers and authorization

- **Remote business MCP.** `/mcp` verifies a bearer as delegated OAuth, Privy or an API key. It selects the catalog based on the verified credential, grant and selected context. The legacy and modern adapters are dispatched by protocol headers. The full delegated adapter strips caller owner input, validates inputs, rechecks client/grant/account and scopes, and separately applies task, catalog, organization, recipient and room checks. It mints account-bound video locators and returns only authorized task-run fields. Current full OAuth budgets are 120 calls per account and 30 per account/tool each minute. In a code program these limits must apply to each underlying operation as well as any outer execution quota. [Authorization](../../lib/mcp/verifyApiKey.ts) · [Full registration](../../lib/mcp/oauth/registerFullOAuthTools.ts) · [Preparation](../../lib/mcp/oauth/prepareFullOAuthTool.ts) · [Execution](../../lib/mcp/oauth/executeFullOAuthTool.ts) · [Rate limits](../../lib/mcp/oauth/checkFullOAuthRateLimit.ts)
- **Limited and selected grants.** Limited discovery contains five personal business tools, a skills tool and two gallery launchers. Scope challenges and execution enforce three read and two write capabilities. The selected-context grant has 27 frozen Context actions, current selected organization authorization, and separate data projections. A new catalog entry must never expand this consent. Standard-only ingestion, credential export, registration preflight, professional roster, streams/tracking and retained-evidence/case operations require explicit treatment. [Limited adapter](../../lib/mcp/oauth/registerOAuthTools.ts) · [Selected actions](../../lib/oauth/selectedContextActions.ts) · [Selected authorizer](../../lib/mcp/oauth/createSelectedContextAuthorizer.ts) · [Full registry exclusions](../../lib/mcp/oauth/registerFullOAuthTools.ts)
- **REST.** `validateAuthContext` requires exactly one of a REST API key or bearer authentication and implements account override and organization checks. Its bearer branch resolves the Privy account. MCP OAuth validation and the MCP resource audience live at a different boundary. The broker should enter an API-owned operation using a verified principal and that operation's delegated projection. Provisioning a broad key for a code program would change the granted authority. [REST authentication](../../lib/auth/validateAuthContext.ts) · [Resource-bound access](../../lib/oauth/resolveOAuthAccess.ts)
- **Native Recoup app.** The canonical `POST /api/chat` starts a durable workflow. Each step builds the native nine-to-eleven-tool sandbox set, with optional skill and interactive question tools. Keeping this surface operational is a regression gate. Its startup prompt savings must be measured separately. [Chat route](../../app/api/chat/route.ts) · [Workflow turn](../../app/lib/workflows/runAgentStep.ts) · [Native tools](../../lib/agent/buildAgentTools.ts)
- **Other first-party agents.** Slack, evaluation and inbound-email paths reach the general agent. Its tool setup fetches the MCP catalog, merges independent Composio actions, then filters excluded names. Some multi-step routines force specific legacy tool names or models. Preserve equivalent operation restrictions inside the broker and test these callers when moving them off the legacy endpoint. Keep Composio's separate entitlements and precedence. Historical conversation tool calls and saved skills must remain interpretable. [General agent](../../lib/agents/generalAgent/getGeneralAgent.ts) · [Tool aggregation](../../lib/chat/setupToolsForRequest.ts) · [Named chains](../../lib/chat/toolChains/toolChains.ts) · [Slack](../../lib/slack/chat/handlers/handleSlackChatMessage.ts) · [Email](../../lib/emails/inbound/generateEmailResponse.ts) · [Evals](../../lib/evals/callChatFunctionsWithResult.ts)
- **UI, files and skills.** The MCP Apps resource `ui://recoup/explore.html` has a thread launcher and a separate app-only sidebar launcher. Both take an empty input. Their identities distinguish an active-chat handoff from starting a new chat. Host-supplied file parameters exist today on music analysis and release-pack asset upload. The modern server serves skills and resources, and older clients use `recoup_skills`. The main connection can project authorized staff skills. The dedicated staff route has its own access test and rejects selected-context grants. Count app-only launchers separately. Test uploaded-file binding, legacy hosts, skill fallback, staff audience and thread placement independently. ## Review and release evidence

Recoup's own OpenAI scan previously flagged a single empty-schema Context dispatcher that hid 27 operations. The repair exposed concrete schemas, corrected names and removed an unexpected conversation-copy input. Subsequent review work added social-refresh quotes, account-scoped results, bounded catalog matching and explicit annotations for deferred outbound effects. The November 26 review record describes an **unsubmitted publisher draft** and conditional missed-report commerce questions. Verify the publisher dashboard and deployed build before reporting the review state.
