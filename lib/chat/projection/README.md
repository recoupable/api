# SDK 7 canonical observation proof — source-only foundation

Not wired into chat admission, model execution, history conversion or persistence. No deployments are admitted by default. API 7 remains incompatible with old readers until the full producer/restore/failure path is integrated and reviewed.

`data-recoup-sdk-observation` stores the exact custom/reasoning-file UI part, origin run and producer step, assistant identity, monotonic ordinal and adjacent fallback span. The provisional text says only that this view cannot display the content. A namespace, client hash, matching database row or echoed seed is never provenance.

`writeProjectionObservation` accepts only newly generated native parts at the future producer boundary. Its result says `requires-readback`: successful public writer calls do not prove downstream storage. This function alone does not distinguish a caller seed; the reviewed producer callsite must enforce fresh-only collection, and callers must reject unverified reserved data before seed/write. It is not an authorization API.

The workflow must await the model producer result, then call `recordProjectionProofStep` as a separate journaled step. That deterministic step validates/copies only the fresh candidate collection; it performs no I/O or nested step invocation. Do not derive proof from aggregate responseMessage. There is no proof-first ordering or atomic stream/message commit claim.

`verifyProjectionObservation` requires already established current account/session/chat authority and server-reviewed exact deployment/workflow/producer-step/proof-step identities. It checks strict legacy or fenced run input, a fresh completed producer result with present proof, a distinct fresh completed proof-step result with present linked output, original bytes/order/span, and actual canonical event readback. An empty producer list fails closed. Trusted producer deployment admission and long-term journal retention are release qualifications, not client fields or a policy introduced here.

`createProjectionEvidencePorts` accepts only the configured server World. Importing it makes no World/key/network call. It uses existing SDK hydration and per-run key resolution, with no new secret. Never log run input: it can contain short-lived credentials. Missing keys, decryption failure, missing/expired/unresolved evidence, partial output, wrong identity, deadline and cancellation fail closed; never fall back to stored caller JSON.

Reads have a five-second verifier deadline, at most 10,000 canonical chunks/16 MiB, at most ten receipt pages of 100 step records, and one MiB per observation. These bounds reject explicitly; nothing is truncated and presented as lossless. Metadata SDK requests do not expose transport AbortSignal: callers are bounded and late promises observed, but underlying transport termination is not claimed. Canonical delivery matching uses finite paginated raw chunks, contiguous absolute indexes and exact single-frame lengths before SDK hydration. It does not open a live reader or treat EOF/cancellation as proof. The failed compiled live-reader cancellation fixture exposed a downstream close race; raw snapshots avoid that path and reject trailing partial bytes that the tolerant SDK decoder can ignore. Incomplete evidence stays unavailable; do not rerun provider/tools to recreate it. The default stream-name/frame contracts are pinned to installed core4.2.4 and checked by the actual SDK fixture.

A required message-write acknowledgement is a separate future integration gate. Unknown proof/persistence/append outcomes remain pending reconciliation; do not blindly reappend or reset cursors. Root-selected compatibility/required-write failure is distinct from Stop and normal completion: preserve known provider usage and completeness separately, no new debit/refund/floor/autocommit/successful fenced release. Normal successful projection retains the existing one post-loop charge path. `handleChatCredits` returning void is not settlement proof.

The compiled offline fixture uses the actual pure writer, separate workflow-awaited proof step, configured-World reader and verifier inside synthetic local workflows, then the installed SDK UI reader. It checks independent completed output and canonical readback with zero network calls. It is not a real Gateway/old-App/native/production acceptance test. Integration still requires fresh-event enforcement, all input writer/seed guards, multi-iteration order, canonical persisted assembly/native restoration, required-write/failure accounting, cursor cuts and both actual App readers, then independent OAuth/Catalog/Packs/Recon review.

Review hardening: canonical projection pairs must occur after their matching `start` while that assistant remains active; a later start or finished/aborted/error context cannot authorize earlier events. Receipt recording and verification use the same strict JSON encoder with one MiB per observation and sixteen MiB aggregate bounds; oversize evidence fails with a sanitized typed limit error.

The World adapter preserves authoritative `run.expiredAt`. Past timestamps reject as expired. Future timestamps fail as unavailable pending configured-World retention qualification: installed CLI treats any non-null metadata as expired while the Web viewer compares timestamps, and the World schema does not settle that difference. Future values are neither admitted nor described as proven expired. Exact SDK expired stubs remain independently rejected; arbitrary caller input fields do not establish run retention status.
