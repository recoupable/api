# SDK 7 canonical projection — integration under review

Chat ingress, history preparation, fresh producer collection and required persistence are wired in source. No deployments are admitted in `projectionProducers`; projected history or generated observations therefore cannot pass production evidence verification until deployment admission and retention are qualified. This source is not release approval.

`data-recoup-sdk-observation` carries the exact custom/reasoning-file UI part, origin run and producer step, assistant identity, ordinal and adjacent fallback span. Fallback text says only that this view cannot display content. A namespace, client hash, matching database row or echoed seed is never provenance.

Interactive ingress verifies current session/chat ownership before proof reads and before claiming a stream or persisting input. The workflow repeats verification after trusted admission/bind and before any user write, same-turn `update_parts`, model conversion or seed. History preparation keeps canonical messages and unrelated tool-answer edits intact; only verified observation/fallback pairs become native parts in model history. Unverified raw custom/reasoning-file and standalone approval parts are rejected. Headless new-chat and room-based paths lack matching origin-chat authority and reject carried observations. The public allowlist is empty, not configurable by request input.

`runAgentStep` passes only newly yielded SDK chunks to `collectCanonicalProjection`. Seeded canonical observations never enter its fresh proof collection. The collector emits canonical events before durable writes, tracks SDK append/upsert rules for provisional span indexes, then uses the actual installed SDK for final canonical assembly and checks every emitted observation's adjacent span. Native SDK UI output and `responseMessages` remain separate for subsequent model iterations. A successful public writer call is not a storage ACK.

The workflow awaits the completed model producer, then invokes `recordProjectionProofStep` as a separate deterministic journaled step. It next verifies fresh completed producer/receipt evidence and actual raw canonical readback under configured producer admission before persisting the projected message. Legacy projected writes require an exact returned message row; fenced writes retain their existing required receipts. Unknown write outcomes fail for reconciliation without automatic provider or write re-execution. There is no atomic stream/message commit claim.

Compatibility generation failures retain observed usage/cost metadata and explicit incomplete usage status in the producer result. Receipt/readback/message failures retain the completed producer result. These failures emit an error finish, bypass new billing and auto-commit, and do not successfully release fenced authority. Unknown usage is not zero. Normal successful projection retains the existing one post-loop charge path. `handleChatCredits` returning void is not settlement proof. Existing unrelated failure finance behavior remains separate.

`verifyProjectionObservation` requires current authority and exact server-approved deployment/workflow/producer-step/proof-step identities. It checks strict invocation shape, fresh completed outputs, distinct receipt linkage, original span and raw canonical delivery. Canonical projection pairs must occur after a matching start while that assistant is active. Another assistant, finish, abort or error cannot authorize them.

`createProjectionEvidencePorts` uses only the configured World and existing SDK hydration/per-run key resolution. Never log run input: it can contain short-lived credentials. Missing keys, decryption failures, expired/unresolved evidence, partial outputs, wrong identities, deadlines and cancellation fail closed. Run metadata `expiredAt` is preserved: past timestamps reject as expired; future timestamps remain unavailable pending configured-World qualification. Installed CLI and Web viewer interpretations differ; future dates are neither admitted nor described as proven expired. Exact SDK expired stubs are independently rejected.

Bounds: five-second verification deadline, 10,000 canonical chunks/16 MiB, ten receipt pages of 100 records, one MiB per observation, sixteen MiB aggregate receipts and at most 256 fresh observations per producer. The producer's buffered per-iteration canonical assembly uses the same chunk/byte bound. Limits reject; nothing is truncated and labeled lossless. Metadata requests lack transport AbortSignal: caller waits are bounded and late promises observed, without claiming transport cancellation. Canonical readback uses finite raw snapshots with contiguous indexes and exact framing, never live-reader EOF/cancellation as proof.

Evidence combines actual Gateway/SDK synthetic-wire tests through `runAgentStep`, installed SDK 6/7 canonical assembly, multi-iteration collection and required-failure control tests; compiled local-World collector/receipt/verifier and ingress rejection; and actual compiled workflow/fence/pricing-boundary tests. The standalone fixture supplies Node's real `require` for generated ESM clients with bundled CommonJS dependencies; no production module is mocked there. These are offline tests, not provider execution or hosted deployment acceptance. SDK event-boundary wire splits are not a full App transport reconnect/cursor qualification. Actual App transport, deployment admission, runtime retention and independent OAuth/Packs/Catalog/Recon review remain gates.
